# Registry Draft Boundary

The proposed public registry is not populated with production-ready mappings.
The current package defines required record concepts in `../SPEC.md` and
`../registry-and-governance.md`, with one deliberately synthetic mapping basis
in `../examples/synthetic-basis.json`.

Before interoperable mapping publication, freeze a profile that defines how
input/context fields bind into complete effect tuples, supported condition
language semantics, implementation comparators, unknown propagation and output
validation. A free-form template or string substitution engine is not silently
part of the core. The candidate CEL profile requires actual cross-library tests.

Future records need stable concept definitions and domain evidence. Do not seed
the public registry by copying OSuite keyword rules and declaring them normative.
Do not count one fictional mapping as real tool coverage. Empty/uncovered
registry entries remain unknown rather than benign.
